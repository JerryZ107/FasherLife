# ADR-013：技术栈选型（Web/H5 + React + Vite + PixiJS）

- 状态：已接受
- 日期：2026-08-18

## 背景

PRD-001 描述的是移动端体验（手机震动、拇指区摇杆、左右滑动转视角），但 Demo 目标含"给上线/投资人演示"，需要易分享。平台与技术栈决定后续所有工程组织。

## 决策

- **平台：Web/H5**，浏览器直接玩，链接即分享，不依赖应用商店审核。
- **UI 层：React + Vite**。所有面板（水族馆、商城、鱼行、装备、任务、图鉴）用 React DOM 写，UI 占工作量 ~70%，用最熟的栈最快。
- **实时场景层：PixiJS**。鱼缸内鱼游动、钓鱼滑块小游戏用 PixiJS 渲染，React 通过 ref 挂载 PixiJS canvas，状态用 React 管理、PixiJS 只负责绘制与动画循环。
- **存档：游戏服务上的账号本**（`data/account-book.json`），按账号 + 密码哈希分槽。账号全柜唯一。登录与注册分开：登录不建号，注册撞名则拒绝。换端口、换设备只要连着这次打开的服务、用同一账号密码就能接上。本机 localStorage 只做缓存，并可记住账密。旧版单槽 `fishing-daily-save-v1` 第一次注册时并入，不提前删。
- **目录按领域分**：`src/fishing`、`src/aquarium`、`src/equipment`、`src/market`、`src/shop`、`src/save`、`src/ui`，与 ADR 术语一一对应。

## 理由

- Web/H5 是"易分享"与"移动端体验"的最佳折中：移动端浏览器可触发震动 API，触控事件可模拟摇杆/滑动，且无需上架。
- React+PixiJS 而非 Phaser 一把梭：UI 面板密集（7:3），React DOM 写面板比 Phaser UI 插件快一个量级；PixiJS 只管两块实时场景，学习与调优成本低于整套 Phaser。
- 存档柜挂在 Vite 上写本地文件：Demo 需要同一份进度在电脑/手机、5173/5177 之间接着玩。不上独立数据库；体量仍远低于单文件 JSON。本机 localStorage 降为缓存。

## 影响

- 项目需建立 React↔PixiJS 桥接约定：React 持有游戏状态，PixiJS 通过订阅状态变化驱动渲染；用户输入在 PixiJS canvas 内捕获后回写状态。
- 震动/摇杆在 Web 端是降级体验（桌面无震动），Demo 演示以移动端浏览器为主。
